Разработка приложения для выборочного проксирования (Split Tunneling) с автоматическим добавлением IP в белый список — это комплексная задача, требующая интеграции клиентского приложения, локальных сетевых настроек ОС и серверной части.

Поскольку ваш прокси-сервер работает на базе Squid, это HTTP/HTTPS прокси. Это накладывает определенные ограничения: HTTP-прокси отлично работают для сайтов (через браузеры), но не все десктопные приложения умеют с ними работать напрямую (в отличие от SOCKS5 или VPN-туннелей).

Ниже представлен подробный план разработки с учетом ваших требований и архитектурных особенностей.

### 1. Архитектура и стек технологий

* **GUI (Пользовательский интерфейс):** Tauri (Rust + React/Vue) или Electron (Node.js + React/Vue). Tauri предпочтительнее, так как на выходе получается легковесный бинарный файл, а Rust отлично подходит для работы с системными сетевыми настройками.
* **Ядро приложения (Локальный клиент):** Локальный прокси-сервис (написанный на Go, Rust или Python), который будет подниматься на ПК пользователя.
* **Маршрутизация сайтов:** Использование PAC-файла (Proxy Auto-Configuration), который локальное приложение будет генерировать и прописывать в системные настройки Windows/macOS.
* **Маршрутизация приложений:** Использование TUN-интерфейса (например, Wintun для Windows) + утилиты вроде `tun2socks` для перехвата трафика конкретных `.exe` файлов и направления его в прокси.

### 2. Серверная часть и безопасность (Автоматическое добавление IP)

**Рекомендуемое решение:** Написать простейший веб-API (микросервис) на сервере (например, на Python/FastAPI или Go). // Используй Pm2 и node js если считаешь что это будет есть меньше мощностей

1. Приложение на ПК определяет свой внешний IP (через сервисы вроде `api.ipify.org`).
2. Приложение отправляет POST-запрос с секретным токеном авторизации на ваш API: `POST /api/whitelist {"ip": "1.2.3.4"}`.
3. API на сервере локально вызывает ваш скрипт `ip_manager.sh add 1.2.3.4`.



### 3. Реализация маршрутизации трафика

**Для веб-сайтов (PAC-файл):**
Это самый надежный способ для браузеров. Приложение генерирует PAC-файл со списком нужных доменов.
*Пример логики PAC-файла:*

```javascript
function FindProxyForURL(url, host) {
    var proxy = "PROXY ваш_ip_сервера:порт";
    // Предустановленные сайты
    if (shExpMatch(host, "*.instagram.com") || shExpMatch(host, "*.twitter.com")) {
        return proxy;
    }
    // Пользовательские сайты (подставляются из настроек приложения)
    if (shExpMatch(host, "*.custom-site.com")) {
        return proxy;
    }
    return "DIRECT";
}

```

Приложение поднимает локальный HTTP-сервер, отдает этот файл по адресу `[http://127.0.0.1](http://127.0.0.1):port/proxy.pac` и прописывает этот адрес в системные настройки прокси ОС.

**Для десктопных приложений (.exe):**
Маршрутизировать трафик конкретного приложения в HTTP-прокси (Squid) сложно.

* *Вариант А (Простой):* Внедрить поддержку системных переменных `http_proxy` и `https_proxy`, которые считывают многие приложения, но не все.
* *Вариант Б (Сложный, но надежный):* Использовать драйвер WFP (Windows Filtering Platform) или Wintun для перехвата трафика конкретного PID (Process ID) приложения, оборачивания его и отправки на прокси. Для этого лучше использовать готовые открытые библиотеки (например, `clash-core` или `sing-box`, которые умеют работать со списками приложений и перенаправлять трафик).

### 4. Поэтапный план разработки

#### Этап 1: Подготовка сервера и API

1. Оставить ваш файл `ip_manager.sh` без изменений, он корректно проверяет наличие IP, добавляет его в `/etc/squid/whitelist.txt` и перезагружает Squid.


2. Разработать микросервис (API) на сервере (порт, например, 8080), который будет принимать запросы на добавление IP.
3. Настроить API на безопасный вызов `ip_manager.sh` через `sudo` без пароля для конкретного пользователя, от которого работает API.



#### Этап 2: Разработка ядра локального приложения (Core)

1. Написать модуль определения публичного IP-адреса пользователя.
2. Написать сетевой клиент для отправки IP-адреса на серверный API для добавления в белый список.
3. Реализовать генератор PAC-файлов, который объединяет предустановленный список сайтов и пользовательский список.
4. Разработать механизм изменения системных настроек прокси ОС (через реестр в Windows или `networksetup` в macOS) для установки сгенерированного PAC-файла.

#### Этап 3: Разработка графического интерфейса (GUI)

1. Создать главный экран с большой кнопкой "Включить/Выключить".
2. Создать раздел "Сайты и приложения":
* Вкладка с чекбоксами для предустановленного списка сайтов.
* Поле для ввода собственных сайтов/доменов.


3. Создать логику хранения пользовательских настроек (локальная база SQLite или JSON-файл).

#### Этап 4: Интеграция и сборка

1. Связать GUI (например, на React) с локальным ядром (Tauri/Rust или Electron/Node).
2. Настроить автозапуск приложения при старте ОС.
3. Добавить функцию периодической проверки смены IP-адреса пользователя. Если у пользователя динамический IP, приложение должно заметить смену IP, отправить запрос к API на вызов `./ip_manager.sh add <новый_IP>` и, опционально, `./ip_manager.sh remove <старый_IP>` для поддержания чистоты списка.


4. Собрать инсталляторы (например, `.exe` / `.msi` для Windows).

#### Этап 5: Тестирование

1. Проверка авторизации и работы скрипта `ip_manager.sh` через API.


2. Проверка маршрутизации: убедиться, что трафик на разрешенные сайты идет через Squid, а остальной трафик — напрямую.
3. Тестирование при смене сетей (переключение с Wi-Fi на мобильный интернет).
